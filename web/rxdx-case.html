Engineering choices,
with reasons.

The goal was to satisfy the RAG brief with an inspectable, deployable system. Each choice responds to the data and constraints of this project.

Retrieval and generation

  • Hybrid searchBM25 handles exact names; embeddings connect phrases such as “skin doctor” to related source content. Rank fusion combines both.
  • Content-aware chunkingKeep a doctor’s profile and schedule together. Split longer pages with overlap and remove repeated website boilerplate.
  • An index that fits the corpusNumPy vectors and BM25 are enough for 427 chunks. No hosted vector database is needed for this demo.
  • Traceable answersNova Lite receives the top eight passages. Numbered citation markers are checked against retrieved sources.

Deployment and operations

  • FastAPI on VercelOne application serves the bot UI, Q&A API, navigator API and this portfolio page.
  • Short-lived AWS identityVercel OIDC exchanges a signed production identity for temporary credentials. The IAM role can invoke only Nova Lite.
  • Serverless conversation handlingRecent history travels with every request so follow-ups work across different server instances.
  • Cost-aware inferenceAWS stays on its Free account plan. Inference consumes eligible credits; app limits are best-effort per instance.

An extension for
questions with constraints.

“ENT in Whitefield, Saturday, Kannada-speaking” requires exact matching over fields. Care Navigator combines model interpretation with deterministic tools.

Observed live behavior

  • Find an ENT doctor in Whitefield on Saturday.The tool returned two matches from the directory.
  • Which one speaks Kannada?A follow-up returned Dr Santosh Nagalikar with one filtered match.
  • A message describing crushing chest pain.The deterministic emergency screen returned its fixed urgent-care response before model inference.

Bounded tool use

Five tools cover doctor search, doctor details, valid branches, valid specialities and booking-request drafts. Tool results supply facts; the model explains them.

The agent stops after eight model calls per turn. Booking requests are drafts: nothing is sent or booked. Review links are searches, not fetched ratings.

Availability comes from a static public snapshot, not a live appointment system.

Understand the scope
before reusing the pattern.

A published demo is evidence of working behavior. Production requirements depend on the client’s data, users and risk.

Source freshness and missing facts

The knowledge base is a 26 August 2026 snapshot of public RxDx pages. It includes missing and inconsistent fields. Clinic schedules must be confirmed, and exact addresses/opening hours are outside this snapshot.

What the tests and metrics prove

The launch suite passed 88 tests and retrieval was evaluated on 30 curated questions. Live checks covered answers, citations, follow-ups and navigator emergency handling. There is no comprehensive end-to-end answer accuracy score, load-test result or measured business ROI.

Free-plan costs and availability

Amazon Bedrock inference consumes eligible AWS Free-plan credits. The account has not been upgraded. Demo availability is finite and depends on remaining credits, plan expiry and Vercel limits. Application rate limits are per-instance and best-effort.

What a client production rollout would add

Depending on scope: scheduled source refresh, wider answer-quality evaluation, durable quotas, monitoring, authentication, access-aware retrieval and approved integrations. The navigator emergency screen is a keyword backstop, not clinical triage.
